# ADR-0005 — Learner Blueprint Architecture

**Status: DRAFT — awaiting explicit approval before any future Blueprint integration sprint (Parent Portal, Learning Compass, Career Intelligence, Behaviour, Notifications, Evidence, Intelligence).** This is a design decision record only. No table, migration, repository, service, route, UI, or test was created or renamed in producing it — confirmed: this document, `sprint-12c-blueprint-architecture.md`, and the implementation-log entry are the only files touched.

**Precedes**: every future sprint that connects the Learner Blueprint to another domain.
**Supersedes**: nothing. Does not rename, delete, or restructure `lib/academicClinic/` or `lib/learnerIntelligence/`.
**Depends on / extends**: `adr-0004-attendance-integration-principles.md` (the read-direction, no-summary-storage, consumer-computes-derived-values discipline this ADR generalizes from Attendance to every domain Blueprint touches), `reference-architecture-specification.md` §9 (Intelligence Standards), `sprint-12c-academic-clinic-hardening.md` (the audit that found `lib/academicClinic/` and `lib/learnerIntelligence/` are, as of today, two independent, non-integrated pipelines — this ADR does not assume that finding is resolved), `docs/sprint-25-educational-constitution-and-migration-strategy.md` (Articles I-XI, the platform's evidence-first principles Blueprint content must obey).

## Why This ADR Exists

Attendance now has a working, gated integration into Report Cards (Sprint 12B), governed by ADR-0004. The next four planned integrations (Parent Portal, Learning Compass, Career Intelligence, Behaviour) all want to reach the Learner Blueprint — but "Learner Blueprint" has never been given one architectural definition. Two things exist in the codebase today under overlapping names: `lib/academicClinic/` (the older PDF-report pipeline, audited in `sprint-12c-academic-clinic-hardening.md`) and `lib/learnerIntelligence/` (the evidence-first "Blueprint" shipped 2026-07-07, built on the Insight primitive and the Projection Engine). Without a frozen definition, every future integration sprint would face the same unanswered questions Sprint 12A answered once for Attendance: what does Blueprint own, what does it only compose, which domain's calculation is authoritative when two exist, and how does the printed artifact stay small while the digital experience grows. This ADR answers those questions once, permanently, the same way ADR-0004 did for Attendance integration in general.

**A factual note this ADR does not paper over**: as documented in `sprint-12c-academic-clinic-hardening.md` §0 and §7, `lib/academicClinic/` and `lib/learnerIntelligence/` are, today, two independently-computed pipelines — they do not share a capability calculation, a pathway calculation, or a report structure. This ADR's "Academic Clinic Engine / Learner Blueprint" terminology split (§4 below) describes the **target relationship**, not the current code's actual behavior. Making the code match this ADR is explicitly out of scope for this sprint (see Explicitly Forbidden, mission) and is not scheduled by this document — it is a prerequisite this ADR surfaces for whoever scopes the first real integration sprint (12D or later).

## 1. Core Definition

**The Learner Blueprint is the permanent longitudinal learner record generated by EduNexus.**

It is explicitly **not**:
- a report card (a report card is one term's official assessment snapshot)
- an AI chat (Blueprint is composed data, not a conversation)
- a Learning Compass session (Compass owns its own sessions and calculations)
- Career Intelligence (Career Intelligence owns its own matching and reports)
- Attendance (Attendance owns its own records permanently, per ADR-0003/0004)
- Behaviour (reserved, not yet built)
- Intelligence itself (Blueprint is a *consumer* of the Projection Engine, per RAS §9, not a second Intelligence engine)

It **is** the official learner profile that composes information from multiple canonical domains into one longitudinal view, without owning any of them.

## 2. Canonical Blueprint Structure

Full section-by-section detail (fields, ownership, freshness, and rendering intent) is in `sprint-12c-blueprint-architecture.md` §2. Summary of the nine sections and their owning domain:

| Section | Owning domain |
|---|---|
| Identity | Core (School/Class/Guardian) |
| Academic Record | Assessments (subject performance, growth trend, CBC competencies), Report Cards (historical snapshots referenced, not recomputed) |
| Attendance Summary | Attendance (Blueprint reads published summaries only — no attendance business logic in Blueprint, per ADR-0004 §4) |
| Learning Compass | Learning Compass (readiness, mastery, recommended path, holiday plan — Blueprint never recalculates) |
| Career Intelligence | Career Intelligence (one concise insight only — Blueprint must never duplicate the full report) |
| Behaviour | Reserved — architecture only, no implementation |
| Teacher Insights | Teacher-authored narrative, snapshot at time of writing |
| Parent Summary | Derived presentation layer — simple language, no jargon, composed from the sections above, not a new data source |
| Learner Growth Timeline | Future extension point — composes milestones from the domains above, owns none of them |

**Rule**: Blueprint owns none of these nine sections' underlying data. It is a read-time (or snapshot-time, per §5) composition layer. This mirrors ADR-0004 §1's "Attendance owns Attendance" pattern, generalized: each section's domain owns that section's truth; Blueprint never becomes a second writer.

## 3. Domain Ownership Matrix

| Domain | Owner | Consumed by Blueprint? |
|---|---|---|
| Assessment | Assessments domain | Yes |
| Attendance | Attendance domain (ADR-0003/0004) | Yes — published summaries only |
| Learning Compass | Compass domain | Yes — one insight, not the full session |
| Career Intelligence | Career Intelligence domain | Yes — one insight, not the full report |
| Behaviour | Reserved (future domain) | Future only |
| Evidence | Evidence domain (`learner_evidence`) | Indirect only — via the Projection Engine, never a direct `learner_evidence` read |
| Report Cards | Report Cards domain | Reference only — Blueprint may cite a report card exists/its term, never recomputes or duplicates its scoring |
| Notifications | Notifications domain | No |
| Analytics | Analytics domain | No |

No duplicated ownership: every row has exactly one owner, and Blueprint appears in no "Owner" column. This satisfies RAS §10.8 (no cross-domain ownership) and the Verification requirement "no duplicated ownership exists."

## 4. Academic Clinic / Learner Blueprint Terminology

**Internal architecture**: `lib/academicClinic/` remains the name of the internal analysis engine. It is not renamed by this ADR.

**Public product**: "Learner Blueprint" is the name schools, teachers, parents, and learners see. `lib/learnerIntelligence/` (shipped 2026-07-07 as the evidence-first Blueprint) is the code that currently serves this public-facing name.

**This ADR does not recommend or schedule a rename of either module.** Developer documentation may continue to reference "Academic Clinic" internally. School/teacher/parent/learner-facing surfaces should primarily say "Learner Blueprint."

**Open item this ADR surfaces but does not resolve** (see "Why This ADR Exists" above and `sprint-12c-blueprint-architecture.md` §7): an uncommitted worktree (`.claude/worktrees/agent-aedf323a0b5ed2eb3`) already contains `lib/learnerIntelligence/reportGenerator.ts` and `app/api/learner-intelligence/pdf/route.ts` — files in exactly the module this ADR designates as the public Blueprint's home. Before any future sprint touches `lib/learnerIntelligence/`, that worktree's relationship to this ADR must be reconciled (merged, rebased, or explicitly abandoned) or the two efforts will collide. This ADR takes no position on which should win — only flags that the collision exists.

## 5. Relationship with Report Cards

A Report Card is the official term assessment snapshot. A Blueprint is the long-term learner record. Neither replaces the other:

- A report card can be generated without a Blueprint existing.
- A Blueprint can exist across multiple report cards (it is longitudinal; a report card is single-term).
- Blueprint's Academic Record section may **reference** a report card (e.g., "Term 2 2026 report card, published") but must never recompute or duplicate the report card's own scoring/ranking logic — that logic belongs exclusively to Report Cards (RAS §10.7, one function per calculation).

---

## 6. Data Freshness Classification

Every Blueprint section must be classified as one of three freshness tiers, following the precedent ADR-0004 §5 already set for Attendance (compute fresh, never cache across requests, unless a future ADR amendment says otherwise):

| Section | Freshness |
|---|---|
| Attendance Summary | Snapshot (published summary from Attendance, not live per-record computation inside Blueprint) |
| Learning Compass | Live (recomputed at read time from Compass's own canonical function) |
| Career Intelligence | Live (recomputed at read time from Career Intelligence's own canonical function) |
| Teacher Insights | Snapshot (authored at a point in time, not recomputed) |
| Report Card reference | Historical snapshot (immutable once published, per Report Cards' own existing precedent) |
| Academic Record (Assessments/CBC competencies) | Live, sourced via the Projection Engine (`recomputeLearnerProjection`), never a direct Operating-Layer read — per RAS §9 |

**Rule**: no Blueprint section may silently mix a live value with a stale cached one under the same "as of" timestamp without labeling which is which. This is the same principle Educational Constitution Article XI ("A number without a name is not neutral") already establishes for Intelligence output generally — Blueprint inherits it, not reinvents it.

## 7. QR Code Strategy

The printed/exported Blueprint stays concise by design: each domain section renders a short summary plus, where the full experience is digital (Learning Compass, Career Intelligence), a QR code linking to that domain's own live surface rather than reprinting its full report. Example pattern:

> **Learning Compass** — Continue your personalized holiday learning journey. *Scan QR code.*
> **Career Intelligence** — Explore careers matched to your strengths. *Scan QR code.*

This keeps "summary on paper, full experience digitally" and prevents Blueprint from growing into an oversized aggregation of every domain's complete output — the direct architectural enforcement mechanism for §2's "one concise insight only" rule on Learning Compass and Career Intelligence. QR **generation** itself is explicitly not implemented by this sprint (Explicitly Forbidden, mission) — this section defines the strategy only.

---

## 8. Guiding Principles

Blueprint must remain: concise, readable, school-friendly, future-proof, longitudinal, domain-independent, composable, non-duplicative. These are not aspirational — §2's "one insight only" rules and §7's QR strategy are the concrete mechanisms that enforce them.

## 9. Constitutional / RAS Compliance

- **RAS §9 (Intelligence Standards)**: Blueprint's Academic Record must read via the Projection Engine, never an Operating-Layer table directly (§6 above makes this explicit per-section, closing the same gap `sprint-12c-academic-clinic-hardening.md` found open in `lib/academicClinic/`).
- **RAS §10.7 (no duplicated business logic)**: enforced by §2/§3 — Blueprint computes nothing itself; it composes.
- **RAS §10.8 (no cross-domain ownership)**: enforced by §3's ownership matrix — Blueprint owns zero rows.
- **ADR-0004's derived-data and no-summary-storage discipline**: generalized in §6 — each section states whether it is live or snapshot, following the same discipline Attendance already established.
- **Educational Constitution Articles I, VI, IX, XI**: Blueprint content must remain evidence-traceable (Article IX), must not have AI invent content beyond what evidence supports (Article VI), and must label confidence/freshness rather than present a bare number (Article XI) — inherited from the underlying domains' own compliance, not re-implemented by Blueprint.
